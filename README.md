## 🏛️ Engineering Philosophy & Best Practices

As a backend engineer, I build software that is **production-ready**, reliable, and maintainable from day one:

```
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│   FastAPI App   │ ────> │  JWT & RBAC     │ ────> │  Business Logic │ ────> │  PostgreSQL DB  │
│  (Async IO)     │       │  Middleware     │       │  (Clean Arch)   │       │  (Indexed/Pool) │
└─────────────────┘       └─────────────────┘       └─────────────────┘       └─────────────────┘
                                                             │
                                                             ▼
                                                    ┌─────────────────┐
                                                    │ ML Model Engine │
                                                    │ (Scikit / Joblib)│
                                                    └─────────────────┘
```

- **Clean Architecture & Separation of Concerns**: Isolating Routers, Schemas, Services, Repositories, and Database Models.
- **Defensive API Design**: Pydantic v2 validation for all incoming and outgoing payloads, strict HTTP status semantics, and centralized error handling middleware.
- **Database Optimization**: Connection pooling with SQLAlchemy, indexed queries, 3NF schema design, and automated version-controlled migrations with Alembic.
- **Security First**: JWT authentication with refresh rotation, Bcrypt password hashing, parameter sanitization against SQL injection, and CORS policies.
- **Containerized Workloads**: Multi-stage Docker builds optimized for minimal image sizes and reproducible production deployments.
